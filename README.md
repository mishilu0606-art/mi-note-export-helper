# mi-note-export-helper

把小米云便签**完整地**导出，并整理成可直接打开的 Obsidian 知识库。

> 重点不是"怎么导出"——那部分 [mi-note-export](https://www.npmjs.com/package/mi-note-export) 已经做得很好了。
> 重点是解决**"导不完"**：导出跑到一半，后面几百条全部失败，而且表面上看起来像是数据没了。

---

## 快速开始

```bash
# 0. 跑起来（首次会自动下载浏览器内核，约 200MB，并弹出登录窗口）
npx mi-note-export
```

**1. 在弹出的浏览器里做一个关键设置**：关掉「关闭所有窗口时清除 Cookie 和网站数据」，允许站点保存数据。
这一步决定了以后每次导出**要不要重新登录**——做完之后，重跑时浏览器窗口"闪一下"就自动登录，什么都不用点。

```powershell
# 2. 自动续跑：反复重跑直到全库拉完，不用人守
powershell -ExecutionPolicy Bypass -File .\auto-resume.ps1
```

```bash
# 3. 整理成 Obsidian vault：先体检出报告，确认后再落盘
python scripts/organize.py <导出目录>
python scripts/organize.py <导出目录> --out <vault> --apply
```

跑完在 `<vault>/_reports/report.md` 看处置报告，用 Obsidian「打开文件夹作为仓库」打开 `<vault>` 即可。

## 三个脚本

| 脚本 | 作用 | 什么时候用 |
|---|---|---|
| `auto-resume.ps1` | 自动反复重跑导出，直到全库拉完 | **首选**，导出阶段 |
| `organize.py` | 敏感隔离、去重、归类、修图片链接、坏图体检 | 导出完成后 |
| `keepalive.ps1` | 每 N 分钟蜂鸣 + 弹窗提醒 | 备选，不方便跑脚本时 |

### auto-resume.ps1

| 参数 | 默认 | 说明 |
|---|---|---|
| `-MaxRounds` | 10 | 最多重跑轮数 |
| `-WaitSec` | 8 | 轮间等待秒数 |
| `-RoundTimeoutSec` | 600 | 单轮看门狗：卡死（网络抖动/服务器无响应）超时强杀该轮，进下一轮自动补 |
| `-NotesDir` | output | 笔记目录，用于统计新增 |

### organize.py

流水线：扫描 → 敏感隔离 → 去重 → 待办归堆 → 碎片识别 → 根目录归类 → 图片链接修复 → 出报告

| 阶段 | 判据 | 去向 |
|---|---|---|
| 敏感 | 身份证 / 手机号 / 银行卡 / 邮箱 / 密码密钥 / 详细地址 | `_sensitive/`（自动写入 `.gitignore`） |
| 去重 | 正文规范化后 SHA256 相同；保留**云端修改时间最新**的（读 `.sync-state.json`，拿不到再退回字数最多） | `_trash/` |
| 待办 | 含 `- [ ]` 未完成项 | `_todo/` |
| 碎片 | 正文 < 20 字且无图片 | `_fragments/` |
| 归类 | 关键词 + bigram 指纹匹配已有分类 | 已有分类 / `_inbox/` |
| 修链 | `![](assets/x.png)` → `![[x.png]]` | 图片收拢到 `_assets/` |
| 体检 | 0 字节 / 文件头损坏的附件 | `_corrupted/`（原文件不动，重跑导出可补） |

三条原则：

1. **默认只体检不写盘**，加 `--apply` 才真正整理
2. **删除一律降级为移动到 `_trash/`**，随时可撤回，绝不真删
3. **优先复用你已有的分类**，不擅自新建，归不掉的进 `_inbox/` 交给你

> 🔒 隐私提醒：`_sensitive/` 已写入 `.gitignore`，能挡住 git 提交；但 **Obsidian 同步到 iCloud / 网盘时 .gitignore 不生效**，含隐私内容请先加密再同步。

## ⚠️ 别做这两件事

| 禁忌 | 后果 |
|---|---|
| 删除缓存目录下的 `browser-data/`（路径见下表） | 浏览器身份丢失，自动登录失效，得重新设置 |
| 运行 `npx mi-note-export --clear-cache` | 同上，Cookie 和浏览器数据一起被清 |

**缓存根目录（按系统）**：

| 系统 | 路径 |
|---|---|
| Windows | `%LOCALAPPDATA%\mi-note-export\cache\` |
| macOS | `~/Library/Caches/mi-note-export/` |
| Linux | `~/.cache/mi-note-export/`（或 `$XDG_CACHE_HOME`） |

<details>
<summary><b>为什么必须反复重跑？（原理与踩坑记录）</b></summary>

### 这个工具解决什么问题

小米的登录态有效期约 **30 分钟**（高频请求下）。导出任务跑得久，就会**部分成功、部分失败**。

### 最大的坑：失败条目极具迷惑性

跑失败的那批，看起来就像"云端已经清空的僵尸条目"。很容易得出错误结论：

- ❌ "我的笔记是不是被小米删了？"
- ❌ "这个工具是不是有 bug？"
- ❌ "算了，剩下的不要了"

**实际上数据好好地在云上，只是登录态过期了。**

判断标准：失败的条数比较多、且集中在某一轮的后半段 → 基本可以断定是超时，不是数据问题。

### 根因（源码级）

`mi-note-export` 的 `src/auth.ts`：`ensureCookie()` **只在进程启动时校验一次** cookie，
之后整个导出过程不再续期。所以一轮跑太久，后半程的请求就是拿过期 cookie 在打，全部失败。

这也解释了为什么"按条数分批切小"没用——它是**按时间**失效的，不是按条数。

### 对策：反复重跑

```bash
npx mi-note-export
```

- 每次重跑 = 重新走登录流程 = 拿到新 cookie
- 工具自带增量机制（`.sync-state.json`），**不会重复下载**，只接着上次的进度走
- 反复重跑，直到待同步为零

### 为什么重跑能自动登录

`launchPersistentContext(BROWSER_DATA_DIR)` 把浏览器身份持久化在 `browser-data/`，
小米认得这台设备，重跑时不用短信验证——再叠加快速开始里的"允许站点保存数据"设置，
浏览器窗口闪一下就完成登录，全程不需要人工点击。

实测参考：约 1600 条笔记，前后登录 3 次跑完。

</details>

## 两阶段策略

| 阶段 | 内容 | 受 30 分钟限制 |
|---|---|---|
| 一、拉数据 | 笔记列表、详情、附件 | ✅ 受限 |
| 二、本地处理 | 去重、分类、改链接 | ❌ 不受限 |

**登录后趁热把阶段一全部干完**，拿到完整数据再慢慢整理。别在 cookie 有效期内去整理——那是浪费宝贵的有效期。

## 已知限制

- 导出失败 ≠ 数据丢失：失败的条目还在小米云端和手机上
- 大批量失败时**先按登录态过期处理**（反复重跑），多次重跑后仍固定失败的那一小批再按类型问题对待
- 空笔记（无标题无内容）会被跳过
- 浏览器身份偶尔还是会失效（隔太久没跑），这时去点一下即可
